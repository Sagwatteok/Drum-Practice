# 공통 악보 형식 초안

도입 순서는 내장 레슨, 검증된 자체 콘텐츠, MIDI, MusicXML이다. 현재 런타임은 4/4 한 마디를 여덟 구획으로 표현하는 `PracticePattern`과 고정 BPM의 `PracticePlan`을 사용한다.

| 객체 | 필드와 의미 |
| --- | --- |
| 악보 | 안정적인 ID, 스키마 버전, 제목, 선택적 난이도·목표, 양의 정수 PPQ, 박자·템포 맵, 마디, 출처·라이선스 |
| 박자·템포 | 악보의 절대 Tick 기준 오름차순 이벤트. 두 맵은 Tick 0에서 시작한다. BPM은 양의 유한 값이다. 박자 변화는 초기 지원 범위에서 마디 시작에 한정한다. |
| 마디 | 0부터 연속인 인덱스, 절대 시작 Tick, 박자표에서 계산한 길이, 노트 |
| 노트 | 안정적인 ID, 절대 시작 Tick, 양의 표기 길이, 악기·아티큘레이션. 선택적으로 보이스, 액센트, 목표 Velocity, 손 사용 안내 |
| 출처 | 내장·생성·가져오기 구분, 생성 규칙 버전·시드 또는 원본 식별자·선택 트랙·변환 옵션. 이용 조건, 표시 의무, 라이선스 미확인을 구분한다. |

480 PPQ에서 4/4 마디는 1920 Tick, 8분음표는 240 Tick이다. 첫 Tick에 킥과 닫힌 하이햇을 따로 기록하면 같은 악보 열과 목표 시각을 공유하며 노트 ID별로 판정한다. 채점은 시작 Tick을 쓰고 렌더링은 표기 길이와 보이스를 보존한다. 물리 Note·CC의 해석과 매핑은 장치 입력에 둔다.

## Tick에서 오디오 프레임으로

절대 Tick에서 각 템포 구간을 유리수 또는 동등한 고정밀 값으로 누적한다. 오디오 프레임으로 투영할 때 절대 위치를 기준으로 한 번만 내림한다. 구간별 정수 프레임을 더하거나, 한 번 반올림한 루프 길이를 반복마다 더하면 오차가 누적된다. 반복과 카운트인은 정밀한 연주 계획 위의 절대 위치로 계산한 뒤 같은 규칙으로 투영한다.

템포 경계와 경계 양쪽의 Tick, 분수 프레임을 만드는 템포의 장시간 반복, 기존 카운트인과 BPM 변경을 비교 테스트한다. 같은 노트 ID의 렌더러 위치와 채점 목표 프레임이 동일한 계획에 대응하는지 확인한다.

## 검증과 이행

- 데이터 오류는 재생·채점 전에 거절한다. 잘못된 박자표·템포, 음수 Tick, 마디 길이·경계 불일치, 알 수 없는 악기, 중복 ID와 같은 악기·아티큘레이션·Tick의 중복 목표를 구분한다.
- 변박·변속, 셋잇단음표, 미지원 표기 길이·아티큘레이션은 지원 오류로 위치와 사유를 표시한다. 가져온 원본을 보존하고, 사용자가 승인한 양자화 등은 변경 내역과 함께 별도의 변환본에 남긴다.
- 키트 구성, 기법과 난이도에 따라 다른 손발 부담, 연타 속도, 악기 부재는 경고로 표시한다. 원본은 바꾸지 않는다. 구체적인 하이햇·림 영역은 실기기 Note·CC 확인 이후에 정의한다.
- 진단은 안정적인 코드, 심각도, 마디·Tick 및 해당 노트 ID를 제공한다. 라이선스가 불명확하면 그대로 표시하고 내장 배포 전에 재사용 조건을 검토한다.
- 먼저 내장 레슨을 Tick 악보로 정의한다. 검증한 **같은 악보와 재생 계획**에서 렌더링 표기와 채점 목표 프레임을 투영한다. 카운트인·반복·BPM 변경은 재생 계획에서 적용한다.
- 이행 중 구형 플레이어에는 손실 없이 투영 가능한 4/4·고정 BPM·8분음표 그리드와 지원 악기·표기만 전달한다. 구형 모델에서 가져오기 파일로 내보내거나 임의의 악보를 구형 모델로 왕복 변환하는 계약은 제공하지 않는다. 두 마디의 가로 위치·동시 타격·BPM 변경·반복을 기준 비교 테스트로 확인한다.
